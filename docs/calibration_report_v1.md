# v0.1 数据事件级校准报告

**日期**: 2026-07-25
**数据**: TIB-2025-001, 902 posts, 758 agents, 151 daily windows (2020-2026)
**模型**: Integrated Propagation-Opinion Dynamics V1.0

---

## 一、数据可行性评估

### 1.1 v0.1 的数据生成过程

v0.1 是通过 MediaCrawler 关键词搜索 + 政府网站爬虫 + YouTube API 采集的**横截面数据集**。数据行是帖子，不是 (agent, time_window) 观测对。

**关键约束**：
- `observed_active` 在所有行恒为 1（每行是一个帖子 = 一次活跃事件）
- 758 个 agent 中仅 84 个（11%）有 ≥2 个帖子
- 151 个时间窗跨越 6 年（2020-2026），但 79% 的帖子集中在 2026 年 6-7 月
- 没有转发边、没有关注网络、没有人口分母
- E（暴露）状态不可观测

### 1.2 能做什么与不能做什么

| 能做 | 不能做 |
|------|--------|
| 估计 A(t) 的聚合曲线 | 估计个体级 P(U→E) 或 P(E→A) |
| 从重复发帖者估计发帖间隔分布 | 校准 β（无级联数据） |
| 估计 reactivation 率 | 校准 k̄_eff（无网络数据） |
| 约束 α₁ 的方向 | 估计精确的 α₁ 值 |
| 检测冲击效应 | 计算精确的 R_eff |
| 设置参数先验分布 | 做个体级模型验证 |

## 二、参数估计结果

### 2.1 衰减率 γ₀

**方法**：从 84 个重复发帖 agent 的 144 个发帖间隔估计。

**结果**：
- 平均发帖间隔：47.5 天（中位数：1.0 天）
- 分布高度偏斜：多数重复帖在同一天内，少数间隔超过 1000 天
- 从中位数估计：P(A→D per day) ≈ 0.5 → **γ₀ ≈ 0.0**（与默认值一致）
- 从均值估计：P(A→D per day) ≈ 0.02 → γ₀ ≈ -3.8

**建议**：使用**γ₀ ∈ [-1.0, 0.0]** 作为先验范围。中位数（1 天间隔）比均值（47 天间隔）更可靠，因为长间隔反映了数据采集的不连续性而非真正的行为模式。

### 2.2 再激活率 r₀

**方法**：从 `previously_active` 和 `reactivated` 标签估计。

**结果**：
- 61 个 previously_active 实例中，11 个被标记为 reactivated
- 再激活率：**18.0%**
- 从中推导：**r₀ ≈ -1.82**（默认值：-4.0）

**解释**：v0.1 中 agent 的"再激活"比模型默认假设的更容易发生。但这可能部分反映了标注策略（停了一段时间再发帖 = reactivated），而非真正的 D→A 转移。

**建议**：使用 **r₀ ∈ [-3.0, -1.5]** 作为先验范围。

### 2.3 观点效应 α₁

**方法**：比较 extreme-stance agent（emotional_outburst, support/oppose）和 neutral agent（informational, neutral_observer）的发帖频率。

**结果**：
- Extreme agent 平均发帖间隔：68 天
- Neutral agent 平均发帖间隔：34 天
- **极端立场 agent 发帖更不频繁**（与 α₁ > 0 的理论预测相反）

**解释**：
- 不意味着 α₁ < 0——而是 emotional_outburst 帖子本身就是稀有事件
- 69% 的帖子是 informational（中性），说明大部分发帖行为不是情绪驱动的
- 在个体级轨迹极稀疏（84 agent ≥2 帖）的情况下，无法检测到 α₁ 效应

**建议**：保留默认 **α₁ = 1.5**，等待 agent 面板数据（≥50 agent × ≥5 帖）后重新估计。

### 2.4 冲击响应 r₁

**方法**：比较冲击日（government document）前后一天的 A(t) 变化。

**结果**：
- 冲击日后 A(t) 平均增加 **+1.1 帖/天**
- 非冲击日平均变化 ≈ 0
- 24 个冲击日中有明显的正向效应

**建议**：**r₁ > 0 得到支持**。保留默认 **r₁ = 3.5** 的阶数，精确值需要更多冲击事件校准。

### 2.5 有效传播数 R_eff

**结果**：**无法从 v0.1 确定**。

原因：
- β 不可估计（无级联数据）
- k̄_eff 不可估计（无网络数据）
- 聚合 r_growth ≈ 0（数据的时间范围被采集窗口人为截断）

**R_eff 的上下界**（基于现有数据的粗略假设）：
- R_eff_min ≈ 0.04（β=0.05, k̄=3, P̄=0.24）
- R_eff_max ≈ 1.29（β=0.15, k̄=20, P̄=0.43）
- 范围跨越临界值 1 → **无法判断传播是超临界还是亚临界**

## 三、校准后仿真验证

### 3.1 参数设置

使用校准后的参数运行模型，与 2026 年 6-7 月的实际 A(t) 对比：

| 参数 | 默认值 | 校准值 | 依据 |
|------|:---:|:---:|------|
| β | 0.15 | **0.03** | v0.1 稀疏、非级联 |
| γ₀ | 0.0 | **-0.5** | 中位数间隔 ~1天 |
| r₀ | -4.0 | **-1.82** | 18% 再激活率 |
| α₁ | 1.5 | 1.5 | 不可检测，保留默认 |
| r₁ | 3.5 | 3.5 | 正向效应确认，保留默认 |

### 3.2 结果

| 指标 | 观测值 | 校准仿真 | 冲击驱动变体 |
|------|:---:|:---:|:---:|
| 峰值 A(t) | 146 (t=46) | 52 (t=46) | 18 (t=45) |
| 总帖数 | 714 | 1,164 | — |
| 与观测的相关系数 | — | **0.49** | **0.70** |
| 峰值时间对齐 | — | ✅ (t=46) | ✅ (t=45) |

### 3.3 解读

1. **相关性 0.49**：模型捕捉到了冲击驱动的时序模式，但未能复现基线活动水平
2. **冲击驱动变体相关性 0.70**：当传播几乎完全由外部冲击驱动时（β→0），模型与数据高度一致——这暗示 v0.1 的 A(t) 模式本质上是被采集行为（外部冲击）而非内生传播驱动的
3. **峰值时间对齐**：模型成功预测了峰值出现的时机（t=46 = 7 月 17 日）
4. **总量级过高**：模型过度生成了活动（1,164 vs 714）——因为 758 个 agent 的基数中，模型假设所有人都可能被激活，而实际数据中大多数 agent 只发过一次帖

## 四、v0.1 对模型的最终约束

### 4.1 已约束的参数

| 参数 | 约束类型 | 范围 |
|------|---------|------|
| γ₀ | 先验区间 | [-1.0, 0.0] |
| r₀ | 先验区间 | [-3.0, -1.5] |
| r₁ | 方向确认 | > 0 |
| N（agent 数） | 点估计 | ~750 |
| |ō|（观点分布） | 先验分布 | 69% 中性, 19% 极端, 12% 支持政府 |
| h̄（情绪分布） | 先验分布 | 均值 0.25, emotional_outburst 均值 0.56 |

### 4.2 未约束的参数

| 参数 | 缺失数据 | 解锁路径 |
|------|---------|---------|
| β | 转发级联 | 跑 cascade collector（已有基础设施） |
| k̄_eff | 关注/互动网络 | 构建 G_s from repost+reply edges |
| α₁ | agent 面板轨迹 | agent 定向采集 |
| α₃ | G_o + 气候数据 | 社区检测 on G_o |
| λ_spiral | 少数派 in 敌对气候 | 需要更强的实验条件 |

## 五、结论

### 5.1 v0.1 对模型校准的价值

v0.1 为 6/29 个参数提供了**先验信息**（γ₀, r₀, r₁ 方向, N, |ō| 分布, h̄ 分布），但**不能独立估计任何单个参数**。

它的主要价值不是校准，而是：
1. **锚定模型规模**：N≈750, 每日帖数≈10-150
2. **提供观点和情绪的先验分布**
3. **验证冲击驱动假说**：A(t) 模式主要由外部事件（采集行为、政府公告）而非内生传播驱动

### 5.2 模型可行性判断

模型在以下方面与数据一致：
- ✅ 冲击响应方向（r₁ > 0）
- ✅ 峰值时序（校准时冲击在 t=46）
- ✅ 再激活率阶数（~18% vs 模型预测的 5-20%）

模型与数据不一致的方面：
- ❌ 基线活动水平（模型持续生成，数据 bursty）
- ❌ 总量级（模型过高）
- ❌ 增长模式（模型 logistic 增长，数据 spike+decay）

这些不一致**不是模型的失败**——它们是 v0.1 作为**非事件追踪数据集**的必然结果。

### 5.3 下一步

1. **P0**：运行 cascade collector → 解锁 β 校准
2. **P1**：agent 面板数据 → 解锁 α₁ 校准
3. **P2**：构建完整 G_s → 解锁 k̄_eff 校准
4. **备选**：使用公开数据集（如 Twitter 事件级联数据）先验证模型，再回到 v0.1

**关键认知**：v0.1 是模型的**先验来源**，不是模型的**验证数据**。真正的模型验证需要一个完整的事件追踪数据集（级联边 + agent 轨迹 + 冲击时间线）。
